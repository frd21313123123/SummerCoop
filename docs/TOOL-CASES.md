# Ящики с инструментами — 0.4.5

Хост учитывает участников, которые загрузили игровую сцену (`Level == 1`),
включая себя. Штатный `spanner set(itemx)` считается первым ящиком. Для второго
и последующих игроков создаются дополнительные обычные наборы с ключами.
Зависшие записи отключившихся гостей без обновления позы более 15 секунд
не учитываются при расчёте новых ящиков, даже если сетевой тайм-аут ещё не истёк.
Магазинные наборы с трещоткой не расходуются: для ручного создания используется
отдельная копия штатного набора.

## Ручное создание и удаление

Откройте **F10 → Читы** или нажмите «Ящики с инструментами» в панели **F7**.
Хост может создать ящик с ключами либо ящик с трещотками. Он появится перед
персонажем хоста на ближайшей поверхности и будет виден всем участникам.

В списке дополнительных ящиков можно удалить выбранный по типу и номеру или
все дополнительные ящики сразу. Исходный набор и купленные наборы не удаляются.
Ящик в руках сначала нужно положить. Если игрок выбрал инструмент из удаляемого
ящика, его выбор сбрасывается. Удаление применяется у всех участников.

Удалённый вручную ящик не восстанавливается при следующем обновлении списка
или переподключении. При увеличении максимального числа одновременно вошедших
игроков обычные наборы снова дополняются до нового числа участников. Ручные
обычные наборы учитываются в этом количестве; трещоточные добавляются отдельно.
Одновременно допускается до 32 наборов с учётом исходного.

Позднее подключение добавляет только недостающие ящики. Выход участника не
удаляет уже созданные предметы, в том числе из рук или транспорта. Поэтому
после выхода игроков ящиков может быть больше, чем оставшихся людей. При
повторном подключении используются имеющиеся ящики.

Автоматические дополнительные наборы появляются рядом с исходным положением штатного ящика
в начале сессии, с промежутками между ними. У каждого фиксированный сетевой ID,
а перенос и перевозку обрабатывает обычная синхронизация предметов `Props`.
Повторный пакет создания не меняет положение уже существующего ящика.

Клиенты принимают создание и удаление только от хоста. Хост повторяет список каждые две
секунды: участник, ещё загружающий сцену, получит ящики после её загрузки.
Список содержит типы и постоянные номера живых ящиков, с номером изменения.
Задержавшийся снимок не может восстановить уже удалённый ящик. Поздний участник
получает только оставшиеся ящики. Актуальные положения ранее перемещённых
ящиков приходят штатным снимком `Props`.
Инструменты и крышка клонируются вместе с родным набором, с собственными
внутренними ссылками. Сохранение дополнительных копий под штатными ES2-тегами
отключено: дополнительные ящики существуют в текущей сессии и создаются заново
при следующей загрузке по числу участников.

Проверки: `tools/build.ps1` собирает мод и запускает тесты ядра и адаптера,
включая сценарии роста количества, повторных обновлений, переподключения,
проверку снимков обоих типов, удаления, устаревших и повреждённых пакетов.
В игровых smoke-отчётах поле `ToolCases` содержит число зарегистрированных
ящиков. Результаты проверки игры записаны в `TOOL-CASES-RESULTS.txt`.

Проверка меню в двух изолированных игровых копиях:

```powershell
.\tools\run-mwcoop-pair.ps1 -Run toolcase-menu-qa -Players 2 -Duration 70 -ToolCaseMenu
```

Она вызывает те же обработчики, что и кнопки, проверяет создание, родные крышки
и выбор инструментов, удаление у обоих участников и повторное создание.
Снимок вкладки записывается рядом со smoke-отчётом.
