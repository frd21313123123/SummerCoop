# GitHub Actions

Workflow [build.yml](../.github/workflows/build.yml) запускается после каждого push, для pull request и вручную через Actions → Build SummerCoop → Run workflow.

На стандартной виртуальной машине GitHub `windows-latest` компилируется ядро с C# 5 и выполняется полный набор проверок, включая настоящие TCP/UDP-сокеты. Игра и её DLL этому этапу не нужны. Отчёт доступен в журнале шага и сводке запуска. Загрузка артефактов не используется: квота хранения аккаунта была заполнена, а для проверки ядра отдельный ZIP не нужен.

Текущий набор ядра содержит 106 проверок; все они прошли локально, включая настоящие TCP/UDP-сокеты. Проверяются также подключение без паузы хоста, сжатие с точным восстановлением, изменения во время загрузки, личные эффекты клиента, последовательные действия болтов, количество пива и посадка с потерянным UDP. `build/SummerCoop.Tests.exe --no-sockets` предназначен для ограниченной среды, явно пропускает только проверку настоящих сокетов и пишет `PARTIAL`. GitHub Actions запускает тесты без этого параметра и требует весь набор.

Отдельный шаг `tools/test-installer.ps1` проверяет поиск Steam-библиотек, установку, резервные копии, проверку актуальности пары DLL, совместимое обновление профиля, восстановление при отказе миграции и при сбое после замены первой DLL, отказ при запущенной игре, повреждённом пакете и неверном загрузчике. Это общий движок установки, который лаунчер встраивает в свой EXE. Результаты попадают в сводку workflow.

Шаг `tools/test-launcher.ps1` запускает 19 тестов лаунчера: аргументы всех пяти режимов, проверка ввода, кавычки путей, маскировка всего пароля, импорт только для своего мира, сохранение настроек и совпадение версий с `src/Core/Model.cs`. Затем компилируется настоящий WinForms-лаунчер на инертном пакете (`DO-NOT-PUBLISH-fixture-Launcher.exe`, не публикуется) и проверяется его командная строка `--install` на изолированной фиктивной игре. GUI-проверки используют отдельный INI в `build`, проверяют загрузку настроек, переключение всех режимов без сброса полей, сохранение правок, ошибки ввода, подсказку про MSCLoader и расположение элементов при уменьшении окна. Результаты попадают в сводку workflow; снимки интерфейса остаются в `build/launcher-tests/screenshots`. Реальная игра не запускается и мод в неё не устанавливается.

Локальный runner удалён по просьбе владельца. Регистрации в GitHub, фонового процесса и автозапуска на компьютере нет.

## Полная сборка

Полная сборка мода требует Mono, Unity, PlayMaker, ES2, Steamworks и MSCLoader из установленной игры. Эти файлы не включены в репозиторий или артефакты CI. На стандартной машине GitHub их нет, поэтому текущий workflow не создаёт установочный ZIP и не проверяет компиляцию игрового адаптера.

Соберите мод на компьютере с установленной игрой и MSCLoader:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build.ps1 -GamePath "E:\SteamLibrary\steamapps\common\My Summer Car"
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\package.ps1
```

Архив и `SummerCoop-Launcher.exe` с файлом SHA-256 появятся в `dist`. Лаунчер встраивает две готовые DLL и инструмент совместимого обновления профиля; игровых сборок в нём нет. Отдельного установщика с 0.4.0 нет: установка, обновление и запуск выполняются лаунчером (подробности: [LAUNCHER.md](LAUNCHER.md), [INSTALLER.md](INSTALLER.md)). Сборка не устанавливает мод в игру и не меняет сохранения. Инструкция установки находится в [README.md](../README.md), игровые проверки — в [QA.md](QA.md).

Действие `checkout` закреплено на SHA официального выпуска. Разрешения workflow ограничены `contents: read`.

Локальная команда `tools/test-native-bindings.ps1 -GamePath PATH` запускает 20 проверок анализа действий против настоящих управляемых классов PlayMaker и игры. Она не вызывает Unity-физику. Эти DLL нужны только локально, остаются в игнорируемом build и не передаются на GitHub. Подробности: [JOIN-INTERACTIONS.md](JOIN-INTERACTIONS.md).
