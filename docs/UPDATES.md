# Самообновление лаунчера

Лаунчер проверяет GitHub Releases репозитория
`frd21313123123/SummerCoop` при запуске и каждые 30 минут. Проверка и
автоматическая установка включены по умолчанию. Их можно отключить отдельно
в настройках; явное `AutoUpdate=0` в `[Lanceur]` сохраняет ручной режим.

Новый лаунчер скачивается по HTTPS. Перед заменой проверяются формат PE и
SHA-256 из `digest` выбранного release asset. Для старых выпусков поддерживается
соответствующий `SummerCoop-Launcher.exe.sha256`. Без контрольной суммы
обновление не запускается. Ошибка сети, лимит API или повреждённый файл
оставляют работающий лаунчер на месте. Кэш описаний выпусков используется
только для чтения новостей вне сети.

Установка разрешена, когда лаунчер свободен: вне игры, запуска игры и лобби.
После завершения загрузки это условие проверяется повторно в потоке окна.
Если обновление найдено во время игры, оно применяется после возвращения.
При ошибке повторная автоматическая попытка возможна через пять минут;
ручная кнопка остаётся доступна.

Замена выполняется служебной копией того же EXE в системной временной папке.
Она ждёт закрытия исходного процесса по унаследованному handle, сохраняет
резервную копию, атомарно заменяет EXE и запускает его по прежнему пути с
прежними аргументами. Новая версия подтверждает открытие окна;
при ошибке замены/запуска или выходе до подтверждения восстанавливается прежний EXE.
При неудаче восстановления резервная копия остаётся в
`%TEMP%\SummerCoop-update-{GUID}\backup.exe`.
При успешном перезапуске временные файлы удаляются, `.sha256` обновляется.
INI с настройками не заменяется.

В папке `SummerCoop-Launcher/` после обновления остаются только
`SummerCoop-Launcher.exe`, его `.sha256` и пользовательский
`summercoop-launcher.ini`. DLL мода и изображения по-прежнему встроены
в EXE; актуальные DLL разворачиваются обычным механизмом запуска мода.

## Запуск актуальной версии через Steam

При обычном запуске лаунчер регистрирует свой актуальный путь в параметрах
My Summer Car (app ID `516750`) в `userdata/*/config/localconfig.vdf`.
Заменяются ссылки на старые SummerCoop/MWCoop; пустой параметр заполняется
автоматически. Аргументы игры и приглашения, настройки других игр и
пользовательские сторонние программы запуска сохраняются. Исходный VDF
сохраняется рядом как `localconfig.vdf.summercoop.bak`.

Открытый Steam может ещё использовать старую команду из памяти. Поэтому
лаунчер также обновляет EXE по прежнему пути и сохраняет эти пути в
`%LOCALAPPDATA%/SummerCoop/steam-launcher.ini`. Следующие самообновления
синхронизируют эти копии, даже если VDF уже указывает на актуальный путь.
Запущенная старая копия передаёт исходные аргументы зарегистрированному
лаунчеру. Известная более новая сборка имеет приоритет над старой.

INI с настройками каждой копии сохраняется. Заблокированные файлы не
перезаписываются; синхронизация повторяется при следующем запуске.
Перезапускать или принудительно закрывать Steam для регистрации не нужно.
Служебные файлы регистрации находятся вне `SummerCoop-Launcher/`.

## Журнал изменений

Раздел «Что нового» и краткий список на главном экране читают описание
соответствующего GitHub Release. Язык выбирается по настройке лаунчера;
если перевода нет, используется английский текст. История помечает установленную
версию по номеру лаунчера, включая номер сборки CI. Полученные описания
сохраняются в кэше выпусков и доступны при следующем запуске без интернета.

Для понятного описания изменений добавьте файл в `docs/changelog/`
с секциями `## ru` и `## en`; необязательна `## fr`. Подробности и пример
находятся в [инструкции по заметкам](changelog/README.md).
При публикации `tools/release-notes.ps1` собирает только новые/изменённые
заметки после предыдущего опубликованного релиза. Если заметок нет,
используются коммиты за этот период. Описание сохраняется в
`build/release-notes-<версия>.md`, записывается в GitHub Release и сводку Actions.
Повторная попытка публикации обновляет описание только у черновика.

## Выпуски после push

После каждого push в `main` GitHub Actions выполняет тесты, расшифровывает
закрытые зависимости, компилирует обе DLL из текущих исходников, собирает
автономный EXE с `/MT` и публикует GitHub Release. Pull request запускает
только проверки и не получает ключ расшифровки.

Версия выпуска состоит из версии мода в `src/Core/Model.cs` и номера
запуска workflow: например, мод `0.4.8` в запуске 53 получает лаунчер и тег
`0.4.8.53` / `v0.4.8.53`. Версия сетевого протокола и игрового мода при этом
не меняется. Следующий push создаст новый номер сборки, даже если версия
мода осталась прежней. Смена совместимости мода по-прежнему требует
обновить его версию и сетевой протокол в исходниках.

Все файлы сначала загружаются в черновик. Публикация происходит только после
проверки полного набора файлов и их SHA-256 на сервере. Опубликованные
выпуски не перезаписываются. Неудачную загрузку черновика можно повторить
через Re-run jobs, новый выпуск можно создать через Run workflow на `main`.

Старый EXE с отключённой автоматической установкой нужно один раз обновить
кнопкой «Обновить» или скачать из Releases. Код уже скачанного EXE невозможно
изменить публикацией на GitHub. После перехода на эту версию последующие
обновления устанавливаются автоматически, если игрок не отключил настройку.

## Проверка локально

```powershell
./tools/build-launcher.ps1
./tools/test-native-updates.ps1 -LauncherPath SummerCoop-Launcher/SummerCoop-Launcher.exe
./tools/test-steam-binding.ps1 -LauncherPath SummerCoop-Launcher/SummerCoop-Launcher.exe
./tools/test-release-notes.ps1 -LauncherPath SummerCoop-Launcher/SummerCoop-Launcher.exe
```

Проверяются выбор версий, каналы, запрет понижения, привязка контрольной суммы
к выбранному EXE, чужие URL, повреждённые файлы, настоящая замена и перезапуск
копии EXE, блокировка файла, сохранение INI и отсутствие служебных файлов
в пользовательской папке. Игра не запускается, основной EXE не заменяется
тестом.

Отдельно проверяется редактирование VDF, сохранение аргументов и других игр,
обновление старой копии, повторная запись Steam старой команды, синхронизация
после следующего обновления, блокировки и выбор более новой сборки. Все пути
в этих проверках заданы явно внутри `build/`; установленный Steam не меняется.
