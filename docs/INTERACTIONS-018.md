# Личные ключи и действия клиента — 0.1.8-alpha

Ключи Home, Satsuma, Ruscko, Hayosiko, Gifu и Ferndale теперь личные. Первый вход использует ключи из нативной копии мира; затем значения сохраняются отдельно в `SummerCoop/personal-keys`, по миру и личности игрока. Для Steam используется Steam ID, при недоступном API — имя LAN-игрока; при повторном подключении используйте то же имя. Ключи сохраняются при изменениях, выходе из сессии, разрыве связи и завершении игры. Этот каталог не передаётся с сохранением хоста.

Ключи и их предметы VanKeys/GifuKeys исключены из общего снимка. Старые общие записи ключей удаляются при обновлении с резервной копией. Нативные предметы остаются у каждого игрока независимо. Номер телефона и общие деньги сохраняют прежнее поведение.

Клиент передаёт фактическое положение и вращение предмета в руке. Хост принимает его только для принадлежащего отправителю предмета, с конечными числами и в пределах четырёх метров от игрока. Перед установкой или другим действием поза идёт по надёжному каналу перед командой. Хост использует эту позу для движения и установки детали; остальные игроки получают её обычной синхронизацией объектов. Долговременный формат контрольной точки не меняется.

Для кнопки Use, обычно F, добавлен маршрут от объекта под прицелом к штатным проверкам его FSM. Он не заменяет проверки питья, занятости руки и наличия бутылок; общий расход выполняет хост, а подтверждённая личная анимация выполняется на клиенте. Результаты локальных поисков Part/HandChild/Distance больше не заменяются промежуточными значениями хоста. Общие предметы остаются общими эффектами и после их перемещения под локальную руку.

Видимость значков болтов зависит от локального режима инструмента игрока. Хост может выполнить команду по скрытому болту только у действительно установленной активной детали; сохраняются проверки размера ключа, позиции и допустимого действия. Подавленные общие эффекты на клиенте отмечаются завершёнными для PlayMaker, чтобы следующий поворот болта стал новым запросом, а переход не зависал.

Автоматические проверки исполняют код ядра и настоящие управляемые определения игры. Игровой сценарий запускается в двух изолированных копиях Unity с отдельными профилями. Диагностический ввод вызывает штатные переходы и событие настроенной кнопки Use; перемещение к цели задаёт тест. Это не подтверждение всех физических клавиш, всех предметов или полного совместного прохождения.

Окончательный кандидат прошёл 94 теста ядра с настоящими TCP/UDP localhost, 17 проверок игровых классов и 12 тестов установщика. В двух настоящих игровых процессах прошли подбор/сброс и повторный подбор после отказа, установка стартера с освобождением руки, затяжка 0 → 1, откручивание 1 → 0, движение двери и питьё через Use с единичным расходом бутылки. Установка выполнялась с точной позой руки, а не прежним расчётным смещением. Обновление копии актуального профиля сохранило прогресс; повторная установка не изменила файлы профиля. Семь старых общих объектов ключей исключены намеренно, чтобы они стали личными.

Обновляйте обе стороны одним установщиком. Исходное одиночное сохранение не нужно удалять. Каталог `personal-keys` следует сохранить при переносе или резервном копировании профиля.
