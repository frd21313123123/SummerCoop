# Инструменты и захват предметов: 0.1.12-alpha

13 октября 2026. Добавлена кнопка **«Восстановить инструменты в чемоданчиках»** в меню F6 после загрузки мультиплеерного мира. Она доступна хосту и клиенту. Восстанавливаются ячейки гаечных ключей и инструментов в имеющихся чемоданчиках игрока, включая отсутствующие объекты: используются сохранённые копии нативных ячеек, их размеров, коллизий, слоёв и расположения. Затем откройте чемоданчик и включите режим инструментов (F1).

Это инструменты для болтов. Личные ключи от машин и дома продолжают сохраняться отдельно. Кнопка не выдаёт машину, не покупает новый чемоданчик и не меняет магазин: без имеющегося чемоданчика показывается сообщение. Набор трещоток поддерживается после покупки и появления его в предметах мира.

Ячейки Tools внутри spanner set и ratchet set исключены из общей синхронизации. Один участник может выбрать свой ключ, сохраняя доступ к тем же инструментам у остальных. Сам чемоданчик, положение, крышка и её состояние остаются общими. В старом профиле удаляются только записи личных ячеек и ссылки на них; нативная сцена сохраняет свои локальные ссылки. Обычные Tools автомобиля и инструменты ремонтной мастерской не затрагиваются. После загрузки мира каждый участник получает нативные ячейки, а кнопка позволяет восстановить их повторно во время игры.

Свежий журнал пользовательской сессии 0.1.11 подтвердил повторяющийся NullReferenceException в FsmStateAction.Init → ActionData.LoadActions → NativeHandLayers.Read → Discover → NativeAdapter.Apply при Take. При таком отказе Authority откатывал весь мир через Registry.Apply(full), поэтому каждая попытка клиента взять предмет приводила к дорогому откату хоста.

Выбор руки больше не перебирает Resources.FindObjectsOfTypeAll, где присутствуют неинициализированные шаблоны PLAYER. Используется действующий PLAYER сцены и FSM с состояниями Part picked и Drop part. Второй PickUp в режиме гаечных ключей не подходит этому условию. При необходимости FSM действующей руки инициализируется перед чтением действий. Настройки слоёв проверяются в Validate до изменения предмета и владения, поэтому ошибка проверки не запускает полный откат мира.

На клиенте Rigidbody теперь создаётся и для деталей, отсоединённых хостом после загрузки, с переданной массой. После подтверждённого захвата корень предмета получает динамическое тело для штатного соединения руки; остальные тела сохраняют физику хоста. Повторные обновления не замораживают корень удерживаемого предмета. Восстановление руки также выбирает действующий FSM переноса. Синхронные записи подтверждённых действий на диск сохранены: предотвращён найденный цикл ошибок и полных откатов, а не изменена гарантия сохранения действий.

Локальные проверки без запуска игры: 109 тестов ядра с TCP/UDP localhost, 22 проверки игровых классов, 12 тестов установщика и 14 тестов лаунчера с проверкой интерфейса. Новые проверки покрывают определение ячеек, обновление старого профиля, сохранность крышки и прогресса, отсутствие изменений NPC-инструментов, повторное обновление и перенос через протокол. Проверка игровых классов отличает два реальных набора состояний PickUp, не читая неинициализированные действия.

Готовый установщик прошёл обновление копии последнего мира с 0.1.11 и повторную установку. Проверены реальная установка, сохранность 38 302 общих сущностей, ревизии 16 101, точного значения денег, исходного одиночного сохранения, нативных файлов и личных ключей от машин. 60 старых записей личных ячеек исключены из общего мира. Повторная установка не изменила ни один файл профиля и его резервных копий. Результаты и контрольные суммы: [TOOLS-AND-PICKUP-012-RESULTS.txt](TOOLS-AND-PICKUP-012-RESULTS.txt).

Эти проверки не запускают Unity-физику и не измеряют FPS. Полное отсутствие фризов, работу кнопки в игре и совместный перенос предметов нужно подтвердить в пользовательской сессии. Обновите хоста и всех клиентов одним установщиком этого выпуска; старые DLL несовместимы с новой сборкой.
